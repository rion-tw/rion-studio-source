## Audit rules

- Read the complete v1 test body before accepting a case.
- Preserve v1 observable inputs, ordering, error, and terminal state.
- An assertion case must execute through `v1_case!` or `v1Case`.
- A test name, comment, or shared fallback without a case assertion is not evidence.
- Fix production behavior in Rust or the Electron presentation adapter before
  marking a mismatching case complete.

## Findings

- The schema-v1 verifier accepted 526 Rust mappings by test-name existence and
  allowed broad fanout; it did not prove assertion-level equivalence.
- All baseline test files deleted or modified between v1.37.0 and the current
  tree are present in the signed source inventory.
- The macro audit confirmed that several old contracts were mapped to broad
  tests that did not independently assert validation, timing, or stop scoping.
- The macro audit restored v1 user-visible errors for disabled/unavailable
  children, duplicate synchronous calls and the 10-second input timeout.
- A synchronous child action failure was incorrectly classified as a manual
  child stop because both paths set the cancellation flag. Failure ownership is
  now checked before propagating the v1 sibling-stop cancellation message.
- Macro timing tests now use an injected waiter and explicit acknowledgements;
  the Q/Digit1 three-iteration case verifies 1000 ms loop waits without
  wall-clock interval assertions.
- Same-role key/click sequences were only serialized per individual effect after
  the Rust move, so another invocation could interleave between hold, wait,
  release, and post-delay. The runtime now owns a role-scoped input-sequence
  lock and held-key cleanup enters the same queue.
- Dense embedded overlay refreshes previously launched an unbounded number of
  concurrent script calls. The Electron adapter now coalesces each WebContents
  to one in-flight refresh plus one trailing refresh and invalidates queued work
  on destruction or failed/main-frame navigation.
- Embedded renderer heartbeat diagnostics now use a per-WebContents one-shot
  watchdog instead of a polling owner in the Electron adapter. Sleep cancels the
  watchdog, resume resets its grace period, and recovery remains independently
  asserted.
- The browser bootstrap audit originally restored v1 automatic graphics for
  missing settings, but that made a fresh installation's first launch disagree
  with the balanced profile seeded into SQLite. Fresh installs now use the same
  balanced profile before and after initialization; granular settings already
  saved by current releases remain authoritative.
- Rust added an `invalid core input:` prefix to every validation message. The
  prefix is removed while retaining `CORE_INPUT_INVALID`, restoring v1
  user-facing error strings without weakening typed error routing.
- Embedded font preferences moved behind `embeddedCreateTab` during the effect
  split, allowing a new session to initialize before its preferences existed.
  Font persistence now completes before role view creation; proxy and CDN
  configuration remain in the live-session phase.
- External compatibility fallback now uses the v1 localized notice text and a
  single Rust predicate that permits fallback only for `auto` plus
  `GAME_PAGE_LOAD_FAILED`. Explicit embedded/external modes cannot accidentally
  enter fallback.
- External Chrome now serializes same-role input, restores held keys after
  lifecycle/focus changes, preserves Windows virtual-key mappings, distinguishes
  CDP probe failures from page unresponsiveness, and gives target discovery its
  full timeout after the DevTools port appears.
- CDN interception now tracks the main frame so only subframe documents are
  rewritten, uses request-stage patterns, and aborts Electron-side fetch probes
  at the Rust effect deadline.
- A stop arriving after a tap hold acknowledgement but during the configured
  hold delay could skip the compensating release. Tap now always dispatches and
  acknowledges release after a successful hold before returning cancellation.
- Resource fail-open previously emitted an `unavailable` status but immediately
  retried the same 2x/4x throttle effect. Unavailable targets now receive a
  release effect and stay at full speed.
- Windows graphics event failures no longer leak the Rust platform error prefix
  into the v1 diagnostics error field.
- Graphics setting updates once again open the restart dialog only after both
  save and diagnostics refresh succeed; failed saves, failed diagnostics and
  non-pending settings do not open it.
- Portable preview normalized an already normalized payload a second time,
  silently dropping the `gameRecovered` migration marker and its warning.
  Preview now parses once and performs exactly one normalization pass.
- Portable macro dependency cycles once again return
  `PORTABLE_MACRO_DEPENDENCY_INVALID` instead of the generic core input code.
- Portable browser font preferences now use the same tolerant normalization as
  live settings, legacy 0.3333 thirds are repaired at the import boundary, and
  per-slot zoom values above the v1 300% ceiling are rejected.
- SQLite replacement tests prove an invalid all-store snapshot is atomic and
  retryable; prepared/committed legacy import journals and active-macro preview
  retention now have independent executable parity cases.
- Legacy macro normalization again rounds percent clicks to two decimals,
  rounds pixel offsets, and removes browser-zoom or runtime-tab shortcuts while
  preserving the macro body and reverting `while_held` to `toggle`.
- Legacy game, role, workspace and macro migrations now reproduce the v1
  fixtures for built-in repair, recovered-game reuse, schema v6/v7 behavior,
  centered-main layouts, role reference fields and browser-directory collisions.
- Windows external Chrome visible-frame alignment now runs through a typed,
  mockable in-process backend. Request validation happens before native calls,
  native failures retain their messages, DPI must be positive, and the exact
  visible target is required within three correction attempts.
- The Electron external-bounds effect now delegates to a pure adapter that
  proves the entire DIP rectangle is converted on Windows and no converter is
  touched on macOS.
